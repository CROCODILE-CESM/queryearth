API reference

Everything below is importable from queryearth, except the shape helpers, which live in queryearth.space.

queryearth: match rules scoped by space, time and dimensions you define to a query.

A Registry holds rules; Registry.query() returns the rules that apply to a query. Space, time and Axis are the base dimensions and Labels the extension that comes with them, all written on the public Dimension class, as your own dimensions are. queryearth.space makes points and polygons (import it as from queryearth import space as sp) and interval() makes times. docs/growth.md lists what queryearth 0.6.0 had beyond this core.

class queryearth.Axis(name: str, unit: str)[source]

A named numeric dimension in one unit, such as grid resolution in km.

A rule gives a range with any of gt, ge, lt and le, and optionally the unit, such as {“lt”: 8} or {“gt”: 2, “le”: 10, “unit”: “km”}; a query gives a number or a closed range (lo, hi). They match when they share a number. queryearth converts no units, so a rule that gives another unit is refused.

class queryearth.Dimension[source]

One kind of scope, such as space, time or grid resolution.

A subclass sets name, the key that scopes, queries and rule files use for it, and implements the three methods below; Python refuses to create one that leaves any out. The Registry calls them and does the rest: it refuses undeclared names, and applies() decides whether a rule applies. A value can be anything the dimension parses, such as a number, a range, a shape or a mapping of several fields; a dimension sees only its own value. A rule file holds each value as the rule gives it, so a value given in Python is plain JSON, apart from space and time.

class queryearth.Labels(name: str)[source]

Names, such as a forcing product or a model option.

A rule gives a name or a list of names, which may use the wildcards * and ? (case-sensitive), such as [“jra”, “era5*”]; a query gives a name or a list of names. They match when a query name matches one of the rule’s.

class queryearth.Registry(dimensions: Iterable[Dimension] = ())[source]

The rules, and the dimensions their scopes use; answers queries.

Every Registry has space and time. dimensions declares the others, such as Axis(“resolution”, “km”), Labels(“product”) or one of your own; a dimension’s name is its key in scopes, queries and rule files.

property rules: list[Rule]

Every rule, in the order added.

add(rule: Rule) → None[source]

Add a rule; Rule.from_feature() makes one from a GeoJSON Feature.

Each scope value is parsed by its dimension. A name the Registry does not have is refused, so a misspelt one never matches by accident, and a code already here raises DuplicateCodeError.

query(**values: Any) → list[Rule][source]

The rules that apply to a query, highest level first, then by code.

values gives the query’s value on any of the dimensions, by name, such as space=sp.box(-60, 30, -50, 40), time=qe.interval(“2020-01-01”, “2020-12-31”) or resolution=8; None leaves a dimension out. applies() says what “apply” means.

to_file(path: str | PathLike[str]) → None[source]

Write every rule to a rule file that from_file() reads back, as indented GeoJSON with each point on one line.

classmethod from_file(*paths: str | PathLike[str], dimensions: Iterable[Dimension] = ()) → Registry[source]

A Registry with the rules of one or more rule files.

dimensions declares the dimensions other than space and time, as Registry() does; a rule that uses any other is refused. Codes must be unique across the files. Raises ValueError naming the file, the feature’s position and its code; nothing is returned unless every rule was read.

class queryearth.Rule(code: str, title: str, message: str, level: str = 'warning', scope: Mapping[str, ~typing.Any]=<factory>, properties: Mapping[str, ~typing.Any]=<factory>)[source]

A rule: a code, a title, a message, a level and a scope.

code is unique, and may be a slash path such as “REGION/ITF/ITF001”: its category is the path before the last slash. level is “info”, “warning” (the default) or “error”. scope maps each dimension the rule constrains to its value, such as {“space”: sp.box(-98, 18, -80, 31), “time”: qe.interval(“2000-01-01”, “..”), “resolution”: {“lt”: 8}}; a dimension it leaves out matches anything, and the Registry checks each value with its dimension when the rule is added. properties holds whatever else the rule carries, such as an instruction or references. The rule keeps every value as given, and to_feature() writes them back unchanged.

property category: str | None

The path before the code’s last slash, such as “REGION/ITF” for “REGION/ITF/ITF001”; None for a code without one.

classmethod from_feature(feature: Mapping[str, Any]) → Rule[source]

A rule from the GeoJSON Feature a rule file holds: its geometry is the rule’s space (null for none) and its JSON-FG time member the rule’s time; its properties hold the code, title, message, an optional level, “dimensions”, the value on each other dimension by name, and anything else, which is kept as given. A Registry checks the values when the rule is added, since it knows the dimensions.

to_feature() → dict[str, Any][source]

The GeoJSON Feature a rule file holds, which from_feature() reads back: the space as its geometry, the time as its JSON-FG time member, and every other scope value in “dimensions”, each as given.

queryearth.interval(start: Any, end: Any) → Interval[source]

A closed interval whose ends are inclusive at their precision.

Ends are ISO 8601 strings, “..” or None for an open end, or date-like values. A date covers its whole day, and a value with a time of day covers its second, even at midnight. With one end a date and the other a time of day, both are written as timestamps.

queryearth.space

Space: points and polygons on the globe, and whether they meet.

Coordinates are float64 (longitude, latitude) in degrees on WGS84, and edges are straight lines in longitude-latitude, as in GeoJSON. Every polygon is normalised once, when it is made: longitudes wrapped exactly, rings cut at +-180 and invalid rings repaired. A ring that goes around a pole is refused; write a polar region as a box to latitude 90 or -90. Matching uses closed sets, so a point on an edge is inside.

Import as from queryearth import space as sp.

queryearth.space.box(west: float, south: float, east: float, north: float) → Space[source]

A box from west to east between two latitudes.

west > east crosses the antimeridian and gives two parts, and -180 to 180 is a full latitude band; to latitude 90 or -90, it covers the pole.

queryearth.space.meets(rule: Space, query: Space) → bool[source]

Whether a query point or polygon meets a rule polygon, as closed sets.

A point on an edge meets the polygon, and shapes that touch across +-180 meet there. A point at a pole has a longitude like any other point.

queryearth.space.point(lon: float, lat: float) → Space[source]

A point, such as a station or a grid cell centre.

queryearth.space.polygon(shape: Any) → Space[source]

A normalised polygon from GeoJSON, shapely or a list of (lon, lat) positions.

Longitudes may use any convention; holes are normalised as separate rings and subtracted. A ring that goes around a pole raises ValueError.

queryearth.space.wrap_lon(x: Any) → Any[source]

x in [-180, 180] with no rounding error, as a float or an array like x.

180 and -180 stay as given. Adding or subtracting 360 is exact, since the remainder and 360 are within a factor of two of each other.
