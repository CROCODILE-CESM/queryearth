Concepts

Rules and their scope

A rule has a code, a title, a message and a level, and may list changes. Its scope says where, when and for what it applies. Rules are written in Python or as records in GeoJSON rule files and packs (a folder with a file per rule), and all are added to a Registry, the rules in memory that you query (see Writing rules). A scope is given on dimensions, such as space, time and grid resolution.

A rule without changes is a warning or a note, such as “these values are climatology, not observations”. A rule with changes suggests what to do: each change is a Change with a target, a key, a value and an optional rationale, such as qe.Change("MOM_input", "DT", 900.0). queryearth never interprets changes; your code applies them, for example to a model’s settings.

The level is a standard logging level, or its name: "info", "warning" or "error". It defaults to logging.WARNING (30) for a rule without changes and logging.INFO (20) for a rule with changes.

A code is a prefix plus three or four digits, such as CRU001, or ERA5-014 (a prefix that ends in a digit needs the hyphen). The prefix is the rule’s category. A Registry can declare its categories, each prefix with a title, and then every code must use one of them:

registry = qe.Registry("mine", categories={"GRID": "Grid and numerics", "ITF": "Indonesian Throughflow"})
registry.next_code("ITF")  # "ITF001", then one past the highest ITF number in use

Registry.next_code() gives a new rule its number. Numbers carry no meaning and are never given twice, withdrawn rules included, so a code always means the same rule.

A category can have subcategories, to any depth: give a subcategory its parent, declared before it.

registry = qe.Registry("mine", categories={
    "DOMAIN": "Domain design",
    "OBC": {"title": "Open boundaries", "parent": "DOMAIN"},
    "GRID": {"title": "Grid and numerics", "parent": "DOMAIN"},
})
registry.category_path("OBC")  # ["DOMAIN", "OBC"]

A rule’s values are written the same way in Python (Scope(dimensions=...)) and in a rule file (the record’s "dimensions" member).

Within a dimension, a rule’s values are alternatives: several polygons, periods, ranges, names or versions mean any of them. Across dimensions, all must hold: a rule applies when its scope and the query overlap on every dimension the rule constrains, and a dimension it leaves out matches anything. So “or” within one dimension is one rule, and “or” across dimensions, such as “the Arctic in northern winter, or the Antarctic in southern winter”, is two rules. A query that leaves out a dimension the rule constrains gets a conditional finding.

Space and time are built into every Registry. Every other dimension is declared, in one list, when you make the Registry, and its name is the key that rules and queries use:

registry = qe.Registry(
    "mine",
    dimensions=[
        qe.Axis("resolution", "km"),
        qe.Labels("product"),
        qe.Labels("variable"),
        qe.Versions("version"),
    ],
)

Scopes and queries give space and time as space= and time=, and the other dimensions in one mapping, such as dimensions={"resolution": 8, "product": "era5"}. A name the Registry has not declared raises UnknownNameError, so a misspelt name never looks like “no rule applies”. Extending queryearth shows how to write your own kind.

A rule file can declare its dimensions itself, so that Registry.from_file() reads it with no Python declarations (see Rule files). Registry.describe() tells a person or a program what a Registry can answer: its categories, its dimensions, the values its rules give on each (Registry.values()) and its rules, as JSON.

Queries and findings

A Query gives values on any subset of the dimensions. “Resolution 8 km” on its own is a complete query. Registry.query() takes a Query or its fields as keywords, and returns a sorted list of Finding objects: highest level first, then those without changes before those with changes, then by code.

A finding carries the rule’s code, title, message, level and changes, plus how it matched:

  • area_fraction and overlap_km2 give how much of the query’s area the rule covers;

  • time_overlap and time_fraction give the overlapping periods and their share of the query’s time;

  • dimensions holds, for each other dimension, a DimMatch with its overlap and, where it can be measured, its fraction of the query’s values. For an axis, overlap lists the parts of the rule’s ranges that the query meets, lowest first, so overlap[0].lo is the lowest matching value.

Finding.to_dict() gives a JSON-ready dictionary.

Conditional findings

When a query leaves out a dimension that a rule constrains, the rule can neither match nor fail. Its finding is conditional: conditional_on names what is missing, for example ("space", "model"). Conditional findings are hidden unless you pass include_conditional=True, which is a quick way to see every rule that might apply:

registry.query(dimensions={"resolution": 8}, include_conditional=True)

Products

product is an ordinary label dimension, matched like variable: exact, case-sensitive names or glob patterns. Coverage limits and other per-product facts are ordinary rules scoped by it, and you query once per product you use. In the toy example, TOY004 is an ERROR for toy_coastal before 2010:

registry.query(time=("2005-01-01", "2005-12-31"), dimensions={"product": ["toy_coastal"]})
# [TOY004] toy_coastal starts in 2010 (2005-01-01..2005-12-31; draft)

Query with what you use

Pass the space and time a product actually contributes: the cells and time steps you read, not a buffered shape. For a model grid, queryearth.converters.grid_outline() gives its outline from the corners of its cells, such as mom6_forge’s grid.qlon and grid.qlat:

domain = qe.converters.grid_outline(grid.qlon.values, grid.qlat.values)
registry.query(space=domain, time=("2000-01-01", "2000-12-31"))

A grid that contains a pole becomes the whole polar cap beyond its outline, since queryearth does not take a ring around a pole: no rule that touches the grid is missed, but area fractions are measured against the cap.

Space

Coordinates are longitude and latitude in degrees, and edges are straight lines in longitude and latitude, as in GeoJSON. Helpers in queryearth.space:

  • point(lon, lat);

  • box(west, south, east, north), where west > east crosses the antimeridian;

  • polygon(shape) for a GeoJSON mapping, a shapely geometry or a coordinate list.

Shapes are normalised once: longitudes from 0 to 360 are wrapped, rings that cross ±180 are split there, and invalid rings are repaired. A ring that goes all the way around a pole raises an error: close it along latitude 90 or -90 first. Matching uses closed sets, so a point on an edge is inside. Area fractions use spherical areas.

A rule with edge=True in its scope ("edge": true in a record) applies where the query’s edge meets its space, rather than wherever they overlap. It is for advice about where a domain’s boundary falls, such as an open boundary that cuts a strong current. A domain inside the space counts, since its edge is too; a domain that holds the whole space does not. The cuts at ±180 are not edges, nor is the pole of a polar cap, so the edge of a cap is its circle of latitude. A point has no edge, and a query without a space gets a conditional finding.

Time

queryearth uses one calendar, the proleptic Gregorian. A time is an ISO 8601 date or timestamp string, a datetime.date or datetime.datetime, a numpy datetime64, or any object with year, month and day attributes (so cftime and pandas values work). ".." is an open end. An end date covers its whole day, so qe.interval("2020-01-01", "2020-01-31") is all of January.

Model calendars such as noleap work unchanged, because every noleap date is a valid Gregorian date. A date that does not exist in the Gregorian calendar, such as 30 February in a 360-day calendar, raises an error.
